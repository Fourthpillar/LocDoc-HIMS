LockDoc Database Script Catalog

This project keeps Flyway SQL in module-owned folders. The app module contains no SQL scripts; it only contains this overview document.

Flyway locations: classpath:db/scripts/common,classpath:db/scripts/outpatient,classpath:db/scripts/pharmacy
Versioning convention: each module owns a reserved block of 100 version numbers, so new modules or new scripts within a module never collide across the combined Flyway location list. Leave gaps within a block for future scripts - don't compact them.
BlockModule
V100-V199common
V200-V299pharmacy
V300-V399outpatient
V400-V499(next module)

1) Common module (V100-V199)

Version File Type Purpose
V100 common/src/main/resources/db/scripts/common/V100__create_tables.sql DDL Creates users, roles, rights, user_roles, and role_rights.
V101 common/src/main/resources/db/scripts/common/V101__seed_default_data.sql Seed Seeds baseline rights, the SUPER_ADMIN role, and the default super-admin user FP_USER.

2) Pharmacy module (V200-V299)

Version File Type Purpose
V200 pharmacy/src/main/resources/db/scripts/pharmacy/V200__create_pharmacy_tables.sql DDL Creates the pharmacy schema: suppliers, medicines, medicine batches, document sequences, purchase orders, purchases, sales, sales returns, and stock ledger tables.
V201 pharmacy/src/main/resources/db/scripts/pharmacy/V201__seed_pharmacy_rights.sql Seed Seeds the PHARMACY_* rights, maps them to SUPER_ADMIN, and adds a PHARMACIST role mapped to all of them.

3) Outpatient module (V300-V399)

Version File Type Purpose
V300 outpatient/src/main/resources/db/scripts/outpatient/V300__create_patient_tables.sql DDL Creates the patients table. This is kept in outpatient rather than pharmacy.
V301 outpatient/src/main/resources/db/scripts/outpatient/V301__seed_outpatient_rights.sql Seed Seeds OUTPATIENT_PATIENT_MANAGE and maps it to SUPER_ADMIN.

Ownership rule

Only the owning module carries its DDL. The app module keeps no SQL files; it only keeps the documentation file so the SQL catalog remains visible without polluting the application resources folder.
